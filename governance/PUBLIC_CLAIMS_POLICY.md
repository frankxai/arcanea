# Public claims policy

Arcanea publishes only evidence-backed counts, statuses, availability, and
rights statements.

## Rules

1. Do not use cumulative word counts as a quality signal. If a count is useful,
   generate it from a named source root and commit.
2. `draft_complete` means the complete intended draft exists. It does not mean
   edited, proofed, rights-cleared, published, or available for sale.
3. `live` requires a working production URL and a current capture or automated
   check. `preview` requires an accessible preview. Everything else is
   `planned`, `experimental`, or `unverified`.
4. Open-source statements must name the exact component and license. Never say
   Arcanea, the whole repository, the canon, or every implementation is MIT.
5. Package, tool, model, skill, command, and repository counts must be generated
   from the release build. Remove the claim when generation is unavailable.
6. A route is not advertised until its primary action succeeds.
7. A manuscript is not a book release until it has a release ID and passes all
   mandatory gates.
8. The public site may describe user ownership only to the extent guaranteed by
   current product terms and actual data handling.

## Release evidence

Each public release records source commit, build result, preview, production
URL, current capture, rights state, approver, and rollback point. The maker may
not be the only verifier or the final approver of a flagship release.
